# 翻译请求、恢复与用量记录

## 分批与长文

默认每批最多 32 条、温度 0.7、并发 4。普通条目按条数分批；发送前将混合批次中的超长条目单独取出，保持处理顺序，再进行片段翻译。默认单条超过 2,400 字符时进入分段流程，片段目标长度为 1,200 字符。配置项分别为 `max_single_item_chars` 和 `max_segment_chars`；未设置前者时，阈值为 2,400 与片段目标长度两倍的较大值。

分段优先选择换行或句末标点，没有合适边界时按长度切分；控制码及受保护字面量保持完整，因此片段可能超过目标长度。片段单独保存，整条拼接、引号处理和最终校验通过后才写入正式译文。

上文按 `context_lines` 选取完整原文条目，默认 8 条。任务预切分时，上文来自当前文件尚需翻译的条目，不包含已经复用或自动填充的条目。长文后续片段追加前片原文，并从前片对齐的引号短词中提取译名供后文沿用；正式词典优先，不注入前片整段译文作为风格参考。

正式翻译请求不发送 `max_tokens`，采用接口自身的默认输出限制。加载和保存翻译配置时移除旧的 `max_context_chars`、`max_batch_chars`、`max_tokens` 和 `max_task_tokens` 字段。任务不按累计 token 用量暂停；词典生成保留独立配置。

## 响应校验与重试

每条译文使用 JSON 记录，格式为 `{"translations":[{"id":1,"text":"译文"}]}`。连续控制码压缩为可逆标记；接收时检查编号、标记数量、顺序、所在行、结构标记的行首行尾位置、文本行数、日语假名残留和引擎专用约束。目标语言为日语时允许假名。结构校验不能判断译文含义、人称或术语是否全部正确，仍需语义校对。

输出截断时，只解析已经完整闭合且编号明确的记录，不补齐未结束的条目。`retry_failed_items_only` 对应“新版回退重试（实验性）”开关，默认关闭：

- 关闭：当前批次全部通过后保存；校验失败先整批重试，仍失败再拆批。
- 开启：立即保存成功子集，仅重试失败项，并附上错误原因及已取得的失败译文。

翻译路径关闭 SDK 自动重试。网络超时与限流由任务层有限重试；认证、额度或配置错误停止后续请求。普通父批与重试子批共享 `max_requests_per_batch` 上限，默认 16 次。每条长文的片段另用一份共享上限，取该配置值与片段数三倍的较大值。所有请求都受任务上限 `max_task_requests`（默认 20,000 次）约束，连续无有效结果也会触发暂停。

请求发出前计数，包含尚未返回的并发请求。暂停后保留已保存的译文和片段，未完成项不写成原文回退；已经发出的请求仍可能返回合格结果并被保存。

## 接口兼容

`stream_mode` 默认为 `auto`，先发非流式请求；遇到已经结束但仅包含用量的 SSE 响应时，任务切换为流式。`enabled` 直接使用流式，`disabled` 禁止自动切换。流式接收检查结束标记、正文和用量，不把思考内容当作译文；断线响应不作为完整译文接收。接口拒绝 `response_format` 时，取消该参数后有限重试。

同一文本两次耗尽输出额度于思考、未返回正文时暂停。`thinking_mode:auto` 仅对官方 DeepSeek 地址的已知支持型号自动关闭思考；代理默认不附加该厂商参数。可显式设置 `enabled`、`disabled` 或 `reasoning_effort`。连接测试使用短文本检查 JSON 响应格式，并支持有限的流式切换。

## 保存与诊断

成功译文按源条目顺序原子写入 `translation_translated.json`。续跑复用已有成功结果；修改词典不会自动删除这些结果。需要按新词典重译时，应先备份，再明确移除对应译文。

翻译输出目录还包含：

- `translation_requests.jsonl`：追加记录请求编号、接口请求 ID、返回型号、请求方式、结束原因和用量；异常时附上响应正文及可用的原文。接口错误信息中的已知 API Key 会脱敏。
- `translation_run_summary.json`：最近一次实际进入请求执行阶段的统计及暂停原因；完全复用结果的续跑不会刷新此文件。
- `translation_fragments.jsonl`：已完成长文片段，用于中断恢复。片段缓存会重新检查控制码和已继承译名，整条仍需拼接校验。

token 统计采用接口报告值；缺少 `total_tokens` 时使用已报告的输入、输出之和。无法取得非零用量的请求计入 `missing_usage`，不估算其费用，因此汇总不能视为完整账单。

## 提示词配置

`system_prompt` 为核心翻译提示词，`user_prompt_template` 为输入模板；界面分别提供编辑页和恢复默认按钮。旧 `prompt_template` 停用，加载时移除，不迁移旧模板内容；缺少新字段时使用新默认值。

两个字段均支持 `{source_language}`、`{target_language}`、`{character_glossary_section}`、`{entity_glossary_section}`、`{context_section}` 和 `{batch_text}`。只替换这些命名字段，JSON 示例的花括号无需双写。编辑时应保留解析器所需的 `translations` 数组及 `id`、`text` 字段。引擎专用标签说明仍会追加到系统消息。
